# FolderPath Memo

フォルダーパスを素早く見つけて再利用するためのWebアプリと、そのWebアプリからWindowsのエクスプローラーでフォルダーを開くためのChrome拡張機能（Manifest V3）です。登録内容はブラウザーのローカルストレージ（と、接続した場合は自分のGoogle Drive）に保存され、Webアプリの公開サーバーには送信されません。

| 部分 | 場所 | 役割 |
| --- | --- | --- |
| Webアプリ | `web/`（Vercelで公開） | フォルダー情報の登録・検索・編集、タグ、バックアップ、Google Drive同期 |
| Chrome拡張機能 | リポジトリ直下の`manifest.json`・`background.js`・`web-bridge.js` | アイコンでWebアプリを開く／Webアプリの「開く」をネイティブホストへ中継 |
| ネイティブホスト | `native-host/` | Windows側でエクスプローラーを起動（ローカルフォルダー・UNCパス） |

Webページは、ブラウザーのセキュリティ上、PCのフォルダーやプログラムを直接開けません。そのため「開く」は、Chrome公式の仕組みであるコンテンツスクリプトとNative Messagingを使い、`Webアプリ → 拡張機能 → ネイティブホスト → explorer.exe`の順に依頼を渡します。拡張機能やネイティブホストがない環境では、「開く」を押すとパスをクリップボードにコピーします。

## 主な機能

- ⭐ よく使うパスをお気に入りに固定
- 🕘 最近エクスプローラーで開いたフォルダーを履歴タブに表示
- 🔍 フォルダ名・メモ・パス・タグを対象にしたあいまい検索
- 📋 パスをワンクリックでクリップボードへコピー
- 📂 Windows 11では起動済みエクスプローラーの新しいタブでフォルダーを開く
- 📝 フォルダ名とは別に、用途などを記録できるメモ
- ✍️ 新規登録時はフォルダーパスを先に入力し、フォルダ名を自動入力
- ↔️ 横スクロールせず編集しやすい、幅広く整列された登録画面
- 🏷 登録済みタグの選択、新規タグの入力、タグ絞り込み
- 🔤 タグ専用編集画面でタグ名・登録件数・並び替え用のよみがなや頭文字を管理
- ↕️ 一覧画面を登録日時（新しい順）・パス順・フォルダ名順で並べ替え
- 💾 `backup-ext_FolderPathMemo_YYYY-MM-DD_hhmm.json`形式のバックアップと復元
- ☁️ Google Drive（フォルダーIDで指定した`FolderPathMemo`フォルダー）の1ファイルに最新版を上書き保存し、複数のPCで同期
- 🔴 前回バックアップ後に追加・編集・削除・利用履歴が変更された件数をボタン横に表示
- 📑 登録件数が多くても見やすい、表形式の一覧画面
- 🔢 ファイル登録があるフォルダーだけに表示される件数バッジ
- 💬 ファイル未登録フォルダーをクリックしたときはリストを開かず一時メッセージで案内
- 🗂 拡張子に応じて色分けされるファイル種別アイコン
- 🎨 フォルダー情報と見分けやすい暖色系のファイル件数・ファイルリスト

Webアプリは、フォルダ名、メモ、タグ、パス、操作ボタンを表形式で表示します。新規登録・編集・削除・お気に入り切り替え・タグラベルの絞り込み・検索・履歴・並べ替え・コピー・Explorer起動・バックアップ・インポートが利用できます。フォルダーの登録・編集時は既存タグを選択し、新しいタグだけを入力できるため、表記ゆれを防げます。リスト内のタグをクリックしても、そのタグで絞り込めます。「タグ設定」からタグ名とよみがな・頭文字を登録すると、漢字を含むタグも指定した読みのあいうえお順で表示できます。読みを登録した未選択タグは緑の文字と枠で区別され、選択中は読みの有無にかかわらず青い背景で表示されます。マウスを重ねると読みが表示されます。読みが未登録の場合はタグ名が表示されます。行はシングルクリックでファイルリストを表示し、ダブルクリックで編集できます。表示条件は横並びのタブで切り替えます。

## Webアプリの公開（Vercel）

Webアプリはビルド不要の静的ファイル（`web/`フォルダー）です。リポジトリ直下の`vercel.json`で、公開するフォルダーを`web`に指定しています。

1. [Vercel](https://vercel.com/)で「Add New… → Project」を選び、このGitHubリポジトリをインポートします。
2. Framework Presetは「Other」のまま、ビルドコマンドなどは空欄で「Deploy」します。
3. 公開されたURL（例: `https://folderpathmemo.vercel.app`）を確認します。

**公開URLが`https://folderpathmemo.vercel.app`以外になった場合**は、拡張機能がそのURLで動くように`manifest.json`の次の2か所を書き換えてから、拡張機能を再読み込みしてください。

```json
"host_permissions": ["https://<公開URLのホスト名>/*"],
"content_scripts": [{ "matches": ["https://<公開URLのホスト名>/*", "http://localhost/*"], ... }]
```

`http://localhost/*`は手元で動作確認するためのものです（例: `cd web` → `python -m http.server 8000` → `http://localhost:8000/`）。

> Webアプリのデータはブラウザーのサイトごとのストレージに保存されます。Vercelの別のURL（プレビュー用URLなど）や`localhost`で開くと、それぞれ別のデータになります。いつも同じURLで開くか、Google Drive同期を使ってください。

## Chrome拡張機能のインストール

1. Chrome で `chrome://extensions` を開きます。
2. **開発者モード**を有効にします。
3. **展開して読み込み**を選び、このリポジトリのフォルダーを指定します（以前の版を入れている場合は、同じフォルダーの中身を入れ替えて**再読み込み**します）。
4. ツールバーの「FolderPath Memo」アイコン（または`Alt + Shift + F`）を押すと、Webアプリが開きます。すでに開いている場合はそのタブに切り替えます。

アイコンが見えない場合は、拡張機能メニュー（パズルのアイコン）でFolderPath Memoをツールバーへ固定してください。

### 以前の版（拡張機能の画面で登録していた場合）からの移行

拡張機能を**削除せずに**再読み込みで更新すれば、拡張機能IDも、拡張機能内に保存されていた登録内容も残ります。そのため次のようになります。

- ネイティブホストの再インストール（`install.ps1`の再実行）は不要です。
- Webアプリを初めて開いたとき、Webアプリにまだ何も保存されていなければ、拡張機能に保存されていた登録内容・タグの読み・Drive設定（クライアントID・保存先フォルダー・自動同期・同期状態）を自動で引き継ぎます。
- 念のため、更新前に以前の画面で「バックアップ」を作成しておくと安心です。引き継げなかったときは、Webアプリの「インポート」でそのファイルを読み込めます。

> **拡張機能を削除すると、拡張機能内のデータは消えます。** 移行が終わるまでは削除しないでください。

> **Edge版から切り替える場合:** Chromeに表示される拡張機能IDはEdgeで使っていたIDと異なる場合があります。必ず`chrome://extensions`に表示されたIDを使って`install.ps1`を再実行してください。インストーラーはChrome専用のNative Messagingレジストリへ登録します。

### ファイル構成

```text
FolderPathMemo\
├─ manifest.json        （拡張機能）
├─ background.js        （拡張機能：Webアプリを開く・ネイティブホストへ中継）
├─ web-bridge.js        （拡張機能：Webアプリのページとの橋渡し）
├─ icons\
│  ├─ icon.svg          （48px・128px用のマスター）
│  ├─ icon-small.svg    （16px・32px用の簡略版マスター）
│  └─ icon16/32/48/128.png
├─ web\                 （Webアプリ。Vercelで公開）
│  ├─ index.html
│  ├─ app.js / app.css  （一覧・登録・検索・編集）
│  ├─ store.js          （ブラウザー内の保存）
│  ├─ extension.js      （拡張機能との通信）
│  ├─ drive.js / drive-ui.js（Google Drive同期）
│  └─ icons\icon.svg
├─ vercel.json
├─ tools\build-icons.py （SVGからPNGを再生成するスクリプト）
└─ native-host\
   ├─ FolderPathNativeHost.cs
   └─ install.ps1
```

拡張機能の起動に必要なのは、上段の3ファイルと`icons`内のPNGです。`native-host`内の2ファイルはExplorer連携のインストール・診断に必要です。

### アイコンを作り直す

デザインを変えたいときは`icons\icon.svg`（および小サイズ用の`icons\icon-small.svg`）を編集し、次のコマンドでPNGを再生成します。16pxと32pxは細部がつぶれるため、フォルダーの形だけを残した簡略版から生成しています。

```bash
pip install cairosvg pillow
python tools/build-icons.py
```

## エクスプローラー連携のセットアップ（Windows）

ブラウザー拡張機能はWindowsのプログラムを直接起動できないため、「開く」ボタンには同梱のNative Messagingホストが必要です。次の操作は初回だけ行います。

1. `chrome://extensions` に表示されるFolderPath Memoの**ID**をコピーします。
2. PowerShellを開き、リポジトリのフォルダーへ移動します。
3. 次のコマンドを実行します（`<拡張機能ID>`をコピーしたIDに置き換えます）。

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\native-host\install.ps1 -ExtensionId <拡張機能ID>
   ```

4. Chromeを再起動します。以降は「開く」で`explorer.exe`が起動します。

Windows 11（ビルド22621以降）でエクスプローラーがすでに起動している場合は、そのウィンドウへ新しいタブを追加します。画面に表示されているウィンドウを優先し、すべて最小化されている場合は最小化されたウィンドウを元のサイズに戻し、復元と再描画が完了してからタブを追加します。キーボード操作は、対象のウィンドウが最前面にあることを毎回確認してから送るため、復元が間に合わないときでも別のアプリへ入力が流れることはありません。対応するウィンドウがない場合やWindows 10では、新しいエクスプローラーウィンドウを開き、そのウィンドウを最前面に移動します。

タブの追加には`Ctrl+T`を使いますが、追加したタブの移動先はキーボード操作ではなくシェル（`Shell.Application`）から直接指定します。`Ctrl+T`の前後で開いているタブの一覧を比較して新しいタブを特定し、そのタブへフォルダーパスを渡します。この経路はキーボードフォーカスを必要としないため、最小化されたウィンドウを復元した直後でも確実に動作します。

シェル経由で移動できなかった場合は、従来どおりアドレスバーを使う経路に切り替えます。この経路では待ち時間を固定せず、`Ctrl+L`はアドレスバーが実際にフォーカスを得るまで送り直し、貼り付けたあとはアドレスバーの文字列を読み戻して一致を確認してからEnterを送ります。貼り付けが届かない場合はアドレスバーへ直接書き込み、それでも失敗したときは追加したタブを閉じてから新しいウィンドウで開きます。フォルダーパスは一時的にクリップボードへ設定するだけで、ナビゲーション開始まで待ってから元のクリップボード文字列を復元します。また、最小化されたウィンドウを元に戻す以外に、既存ウィンドウの位置や最大化状態を変更する処理は行いません。

### 「開く」の動作が変わらないとき

拡張機能のファイルを新しくしても、Native Messagingホストは`install.ps1`を実行し直すまで**古い実行ファイルのまま**です。`FolderPathNativeHost.cs`を更新したときは、`native-host`フォルダーの中身が最新であることを確認したうえで`install.ps1`を実行し直してください。

拡張機能を更新していても、`explorer.exe`を操作しているのは以前のホストであることがあります。次のコマンドで、実際にインストールされているホストのバージョンを確認できます。

```powershell
& "$env:LOCALAPPDATA\FolderPathMemo\FolderPathNativeHost.exe" -version
```

`FolderPathNativeHost.cs`の`HostVersion`と一致しない場合は、`install.ps1`をもう一度実行してください。インストーラーは新しいホストを別名でビルドしてから差し替え、差し替え後のバージョンを表示して検証します。コンパイルに失敗した場合は、動作中のホストを壊さずにエラー内容を表示して中断します。

うまく開けないときは、直前の1回分の動作記録が`%LOCALAPPDATA%\FolderPathMemo\last-open.log`に残ります。どの段階で失敗したかがわかるため、問題を報告するときはこのファイルの内容を添えてください。**このファイルが作られない場合は、古いホストが動いています。**

ホストはユーザー単位で`%LOCALAPPDATA%\FolderPathMemo`へインストールされるため、管理者権限は不要です。ホストが未設定、または起動できない場合は安全策としてパスをコピーします。

「連携設定を確認してください」と表示される場合は、拡張機能を再読み込みしたことでIDが変わっていないか確認し、現在のIDでもう一度インストールコマンドを実行してください。インストーラーはWindows PowerShell標準のC#コンパイラーで動作する互換構文を使用しています。

すべてのファイルを入れ替えた後は、最初に次のコマンドでインストーラーが存在することを確認してください。

```powershell
Test-Path .\native-host\install.ps1
```

`True`と表示されたら、現在の拡張機能IDで上記の`install.ps1`を実行してください。インストーラー自身が、実行ファイル、Native MessagingのJSON、Chromeレジストリ、`allowed_origins`のID一致まで検証します。`False`の場合は、ローカルのフォルダーが最新版ではないため、`native-host\install.ps1`と`native-host\FolderPathNativeHost.cs`を配置してから実行します。

### 「開く」を押すとパスがコピーされるだけのとき

Webアプリは、Explorerで開けなかったときにパスをクリップボードへコピーします。表示されるメッセージで原因を切り分けられます。

- 「Explorerで開くには拡張機能が必要です」：このページで拡張機能が動いていません。拡張機能が有効か、Webアプリを`manifest.json`に書いたURLで開いているかを確認し、拡張機能を再読み込みしてからページも再読み込みします。
- 「開けなかったため…（Specified native messaging host not found.）」など：拡張機能は動いていますが、ネイティブホストが未設定です。上記の`install.ps1`を現在の拡張機能IDで実行し、Chromeを再起動します。

### アイコンを押してもWebアプリが開かないとき

1. `chrome://extensions`でFolderPath Memoが有効であり、赤いエラーが表示されていないことを確認します。
2. FolderPath Memoの**再読み込み**を押します。
3. `Alt + Shift + F`でも開けない場合は、WebアプリのURLをブックマークして直接開いても使えます（「開く」には拡張機能が必要です）。

## Google Driveへの保存

Webアプリの「Google Drive」ボタンから、登録内容をGoogle Driveと同期できます。保存先は既定でGoogle Driveの[FolderPathMemoフォルダー](https://drive.google.com/drive/folders/1u6N_eEqh7PDCpA4Fm8gqXYJmHMPl-SDv)（フォルダーIDで指定）です。保存先はDriveダイアログの「接続設定」でフォルダーのURLまたはIDを入力して変更できます。既存フォルダーへ書き込むため、Googleへの接続時には`drive`（Google Driveの表示・編集）権限を要求します。

Driveには`backup-ext_FolderPathMemo.json`という1ファイルだけを置き、保存のたびに上書きします（日時付きのファイルは増えません）。

- **Driveに保存（上書き）**：この端末の内容でDriveのファイルを上書きします。ほかの端末がDriveを更新していた場合は、上書きしてよいか確認します。
- **Driveから読み込む**：Driveの最新版で、この端末の登録内容を置き換えます。
- **自動で同期する**（既定でオン）：登録内容を変更すると約2秒後に自動でDriveへ保存し、Webアプリを開いたときにDriveの方が新しければ自動で読み込みます。Driveとこの端末の両方に変更がある場合は、どちらも上書きせずに「要確認」と表示するので、Driveダイアログで保存か読み込みを選んでください。

Driveボタンには同期の状態が表示されます。

| 表示 | 意味 |
| --- | --- |
| 🟢 同期済み | Driveと同じ内容です |
| 🔵 同期中 | Driveへ保存・確認しています |
| 🟠 未同期 | Driveにまだ反映されていない変更があります |
| 🟠 要確認 | Driveとこの端末の両方に変更があります。ボタンを押して保存か読み込みを選びます |
| 🔴 未接続 | Googleに接続できていません。ボタンを押すとそのまま接続し、同期します |
| 🔴 エラー | 同期に失敗しました。ボタンにマウスを重ねると理由が表示されます |

Googleのアクセストークンは約1時間で切れます。ブラウザーは操作なしにGoogleのログイン画面を開けないため、期限が切れるとボタンが「未接続」になります。ボタンを押すと（一度許可していれば同意画面なしで）接続し直して同期します。同期できなかった変更は、Webアプリを開いている間、15分ごとに自動で送り直します。

WebアプリにはGoogleのクライアントIDが含まれていないため、初回だけ次の設定が必要です。

1. [Google Cloud Console](https://console.cloud.google.com/)でプロジェクトを作成し、**Google Drive API**を有効にします。
2. 「OAuth同意画面」を設定し、自分のGoogleアカウントをテストユーザーに追加します（公開ステータスは「テスト」のままで使えます）。
3. 「認証情報」→「OAuthクライアントIDを作成」で、種類に**ウェブ アプリケーション**を選びます。
4. 「承認済みのJavaScript生成元」に、Driveダイアログの「接続設定」に表示されるWebアプリのURL（例: `https://folderpathmemo.vercel.app`）を登録します。以前の拡張機能用に作ったクライアントIDを使い続ける場合も、この登録を追加してください（リダイレクトURIは不要になりました）。
5. 発行されたクライアントIDをDriveダイアログに貼り付けて「保存」し、「Googleに接続」を押してログインします。

> Googleのログイン画面はポップアップウィンドウで開きます。開かない場合は、Chromeのアドレスバーでこのサイトのポップアップを許可してください。
>
> 「同時に要求できないスコープ（scopes that cannot be requested together）」というエラーが出る場合は、ほかのアプリと共用しているクライアントIDで、別の権限がすでに許可されています。FolderPath Memo専用のクライアントIDを作るのがおすすめです。

## データ形式

バックアップは `version`、`exportedAt`、`items` を含む JSON ファイルです。インポートすると現在の登録内容はバックアップの内容で置き換わります。
